# Well-Architected findings and remediation

Tracks every finding from the Well-Architected review and the authentication/authorization review, and how each one is fixed and validated. Each fix lands test-first in its own commit and updates its row here.

**Deployment target:** a single Mac server running the Docker Compose stack. There is no cloud deployment, so `docker-compose.yml` is the production deployment, not only a development convenience.

**Status:** `Open` · `Partially fixed` · `Fixed` (code merged on this branch, with validation named) · `Planned` (scheduled for a later phase)

**Validation sources:** unit/HTTP tests (`npm test`), Postgres integration tests (`npm run test:integration`), and the live security-layer checks against the composed stack (`scripts/validate-security.sh`), which also run in CI.

## Local Mac server findings

These findings come from the local deployment target. Each was checked against `docker-compose.yml` and the API configuration.

| ID     | Pillar                 | Risk   | Finding                                                                                                                                                                                            | Proposed fix                                                                                                                                                                                                       | Status |
| ------ | ---------------------- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| HOST-1 | Security               | High   | The web port is published on every interface over plain HTTP (`docker-compose.yml`, `${WEB_PORT:-8080}:8080`), so passwords and bearer tokens cross the network in cleartext                       | **Decided:** the app is used across a home or office network, so nginx serves HTTPS with a locally trusted certificate (mkcert) and HSTS, port 80 redirects to it, and each client device trusts the local CA once | Open   |
| HOST-2 | Reliability            | High   | No backups: all data sits in the `db-data` volume inside Docker Desktop's VM disk, which Time Machine doesn't capture consistently; `docker compose down -v` or a damaged VM disk loses everything | Scheduled `pg_dump` (launchd) to a host folder Time Machine covers, with retention; a restore script; a restore check in `validate-deploy.sh`                                                                      | Open   |
| HOST-3 | Security               | High   | Compose has no production mode: secrets fall back to published defaults (`JWT_SECRET`, `POSTGRES_PASSWORD=todo`) and demo users are on by default. This is the compose side of AUTH-13             | A production override (`docker-compose.prod.yml`) with `NODE_ENV=production`, required secrets (`${JWT_SECRET:?}`), no demo users, and a `.env` with mode 600 that is never committed                              | Open   |
| HOST-4 | Reliability            | Medium | Uptime depends on the Mac: restart policies only apply once Docker is running, and sleep or a power cut stops the service                                                                          | Docker Desktop "start when you sign in" (or Colima under launchd); disable system sleep; "start up automatically after a power failure"; documented in the README                                                  | Open   |
| HOST-5 | Operational excellence | Low    | Container logs grow without limit (default `json-file` driver, no rotation) on the server's only disk                                                                                              | `logging: max-size` and `max-file` on every service                                                                                                                                                                | Open   |
| HOST-6 | Security               | Low    | Encryption at rest depends on the Mac's disk encryption                                                                                                                                            | Require FileVault, and keep backups in an encrypted location (documented)                                                                                                                                          | Open   |
