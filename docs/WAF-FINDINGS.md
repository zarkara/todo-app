# Well-Architected findings and remediation

Tracks every finding from the AWS Well-Architected review and the authentication/authorization review, and how each one is fixed and validated. Each fix lands test-first in its own commit and updates its row here.

**Status:** `Open` · `Partially fixed` · `Fixed` (code merged on this branch, with validation named) · `Planned` (scheduled for a later phase)

**Validation sources:** unit/HTTP tests (`npm test`), Postgres integration tests (`npm run test:integration`), and the live security-layer checks against the composed stack (`scripts/validate-security.sh`), which also run in CI.

**Phase 2 changes proposed by review 2.** Move these before the first production deploy, because they're set when resources are created or are needed to fix the "deploy" rows: OPS-1 (at least the ALB/ECS settings), SEC-6 (RDS encryption at rest), REL-4 (backups, point-in-time recovery, deletion protection), a minimal OPS-2 (JSON logs and alarms) and AUTH-9 (login events). AUTH-3 (token revocation) is now about an hour of work, because every request already loads the user.
